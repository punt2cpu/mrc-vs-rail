# mrc-vs-rail

Containerlab lab comparing a classic rail-optimized fabric (eBGP, BFD, per-flow ECMP) with an MRC-style one (static SRv6 uSID, the host sprays every packet over 16 paths, no routing protocol).

Write-up with topologies, results and conclusions : [punt2cpu.net/2026/10/26/mrc-vs-rail-lab](https://punt2cpu.net/2026/10/26/mrc-vs-rail-lab/)

> Best attempt to mimic MRC in a virtual lab. Real MRC lives in the NIC, here a small Python app plays the NIC. Everything runs on veth links, far from real hardware timing.

## Run

Needs kernel 6.1 or newer, Ubuntu 24.04 works. Installs docker and containerlab if missing.

```bash
git clone https://github.com/punt2cpu/mrc-vs-rail.git && cd mrc-vs-rail
sudo ./lab.sh all                                 # both labs, all tests, BFD and probes at 50 ms
sudo PROBE_MS=1 SPIN=1 BFD_MS=10 ./lab.sh all     # fast detection: 1 ms probes, BFD 10 ms
sudo ./lab.sh all 10                              # 10 rounds
sudo ./lab.sh summary                             # median (min-max) of everything in results/
sudo ./lab.sh watch rail                          # second terminal, live view per QP
```

`./lab.sh` without arguments lists all commands.

## Tests

| test | fault | how |
|---|---|---|
| spray | none | traffic only, packets per uplink |
| link | T0-T1 link drops everything for 10 s, carrier stays up | `tc netem loss 100%` on both ends |
| switch | T1 stops forwarding for 10 s, BGP and BFD stay up | nftables chain on the `forward` hook with `policy drop`, control plane traffic goes through `input`/`output` and isn't touched |
| flap | same link loses carrier for 2 s every 10 s, 4x | `ip link set down/up` |
| t0down | whole T0 down for 10 s | all its links `down` |

Traffic : 32 QPs from srv1 to srv2, UDP with sequence numbers, 1000 packets per second per QP. 1 lost packet = 1 ms of that QP.

## Files

- `configs/rail`, `configs/mrc` - one file per device : links, FRR and Linux config
- `labs/` - containerlab topologies and node configs, generated by `gen.py`
- `tools/flows.py` - traffic sender, receiver and the mrc-style path probing
- `tools/summary.py` - lost packets per QP and the summary table
- `results/` - one folder per run (not in git)
